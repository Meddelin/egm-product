# Shared Execution Instructions (`egm-product`)

All skills and subagents in `egm-product` must adhere to the following operational rules at all times:

## 1. Host Repository Sandbox Isolation
*   **Never Mutate Production Application Code**: `egm-product` only creates or modifies product context contracts (`PRODUCT_CONTEXT.md`, `METRICS.md`, `.pm/schemas.md`, `.pm/ui_tokens.md`) and product feature artifacts under `docs/product/<feature-slug>/` (`opportunity_brief.md`, `prd.md`, `pm_review_report.md`, `prototype.html`).
*   **Zero Build or VCS Side Effects**: Never modify `package.json`, `pyproject.toml`, application source files, or existing directory `README.md` contracts generated by `egm-bootstrap`. Never run `git commit` or `git push` autonomously.

## 2. Artifact-First Delivery
*   Always write or update the target Markdown or HTML artifact on disk **before** presenting a gate or summary to the Product Manager.
*   Keep chat responses concise: link to the saved artifact and surface only the specific trade-offs, open questions, or gate options requiring a decision.

## 3. Plain-English Standard
*   Write in direct, objective, falsifiable prose.
*   **Banned Vocabulary**: Never use validating or flattering adjectives (`great`, `brilliant`, `smart`, `correct`, `perfect`, `excellent`, `spot-on`), polite apologies, or promotional buzzwords (`seamless`, `robust`, `blazingly fast`, `seamlessly`, `effortlessly`, `literally`, `drastically`, `obviously`).

## 4. Default to Stress-Testing & System Grounding
*   Challenge unverified product assumptions against repository facts in `PRODUCT_CONTEXT.md`, `.pm/schemas.md`, and `METRICS.md`.
*   Every requirement (`REQ-ID`) must carry a machine-verifiable **Evidence Citation Tuple** (`[file:symbol_or_line]`) and a readiness classification (`READY_NOW`, `ADAPT_NOW`, or `BLOCKED_NOW`) under strict **`BLOCKED_NOW > ADAPT_NOW > READY_NOW`** precedence.

## 5. Interactive Question Protocol
*   **Open-Ended Clarification**: Ask at most **one** open-ended question per turn in plain text when exploring problem framing, personas, or metric baselines.
*   **Structured Checkpoint Gates**: When presenting a readiness, triage, section-approval, or review-resolution gate, call the structured question tool (`ask_question` / `AskUserQuestion` / `request_user_input`) with a single single-select question (`len(questions) == 1`, `is_multi_select: false`) and put the recommended option first prefixed with `(Recommended)`:

```json
{
  "questions": [
    {
      "question": "<Gate question text>",
      "is_multi_select": false,
      "options": [
        "(Recommended) <Primary action>",
        "<Secondary action>",
        "<Revision or escape action>"
      ]
    }
  ]
}
```

## 6. Contradiction Auditing Across Artifacts
*   Before finalizing `opportunity_brief.md`, `prd.md`, or `prototype.html`, verify that no requirement classified as `BLOCKED_NOW` appears inside the active Day-1 MVP scope (`## Goals`, `## Critical User Journeys (CUJs)`, or `## Scope Classification (READY_NOW / ADAPT_NOW)`). All `BLOCKED_NOW` items must reside exclusively under `## Prerequisite Ledger (BLOCKED_NOW)` and be listed as out-of-scope in `## Non-Goals`.
